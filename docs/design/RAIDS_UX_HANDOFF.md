# Рейды — UX/UI handoff задачи #53

Статус: готово к просмотру Павлом. Реализация остаётся дизайн-прототипом и не подключена к production API.

## Цель экрана

Дать участнику Кабанды один понятный центр управления рейдами: быстро вернуться в активный рейд, увидеть ближайшие планы, выбрать готовый маршрут и найти завершённые поездки.

## Визуальное направление

Главный референс — мобильный макет, переданный Павлом 31 августа 2026 года. Перенесены его композиция, красно-чёрная иерархия, плотность, секционные заголовки, карточка активного рейда, компактные строки и три карточки маршрутов.

Сознательные продуктовые отличия:

- внизу остаются четыре существующих раздела `Главная / Карта / Рейды / Кабанда`, а не пять разделов из референса;
- системная строка iOS не рисуется внутри HTML — её даёт устройство;
- изображения маршрутов временные и используют существующие материалы Кабанды;
- минимальные интерактивные цели сохранены около 44 px даже там, где референс визуально плотнее.

## Информационная архитектура

1. `Сейчас`: один активный рейд или компактное пустое состояние.
2. `Предстоящие`: ближайшие запланированные рейды, дата и свободные места.
3. `Доступные маршруты`: горизонтальная snap-лента; на 390–430 px видны три карточки, на 320 px — две с продолжением.
4. `История`: компактный список завершённых рейдов.

Вертикальный список маршрутов рассматривался как альтернативный вариант и отклонён: он вытесняет историю ниже первого экрана и делает hub похожим на каталог. Горизонтальная лента сохраняет иерархию референса и даёт быстрый обзор.

## Основные переходы

- `Новый рейд` открывает bottom sheet с вариантами `Поехали сейчас` и `Запланировать`.
- `Запланировать` открывает отдельный шаг даты и времени, затем общий выбор участников.
- карточка готового маршрута открывает отдельный routable preview.
- `Поехать по маршруту` открывает отдельный экран выбора участников.
- быстрый старт ведёт в состояние открытого lobby, планирование — в подтверждение предстоящего рейда.
- Escape и нажатие на затемнение закрывают bottom sheet.
- выбранный маршрут и источник старта сохраняются в URL, поэтому reload и Back/Forward не меняют контекст.

## State matrix

| Область | Состояния | Как открыть в прототипе |
| --- | --- | --- |
| Hub | active, idle | `variant=active`, `variant=idle` |
| Hub loading | skeleton | `variant=loading` |
| Предстоящие | empty / длинное имя / 0 подтверждений / доступен старт | `variant=upcoming-empty`, `variant=upcoming-cases` |
| Каталог | error / partial error / fallback cover | `variant=catalog-error`, `variant=partial-error`, `variant=fallback` |
| Hub | empty / offline stale | `variant=empty`, `variant=offline` |
| Preview | normal / archived / partial error / fallback | `screen=preview`, дополнительно соответствующий `variant` |
| Планирование | дата и время | `screen=schedule` |
| Участники | default / 20 человек / retry error | `screen=participants`, `participant=long`, `participant=error` |
| Результат создания | lobby / scheduled | `screen=scheduled&origin=quick`, `screen=scheduled&origin=schedule` |
| New raid | bottom sheet | кнопка `Новый рейд` |

Для ручного ревью можно добавить `review=1`: появится служебный переключатель экранов и состояний. В продукте его нет.

## Доступность

- секции связаны с заголовками через `aria-labelledby`;
- icon-only кнопки имеют `aria-label`;
- bottom sheet имеет `role=dialog`, `aria-modal` и закрывается по Escape;
- focus trap удерживает клавиатурный фокус внутри sheet, после закрытия фокус возвращается на `Новый рейд`;
- фокус имеет заметный синий outline;
- состояния активного рейда обозначены текстом, а не только красным цветом;
- чекбоксы — нативные, CTA блокируется при пустом составе;
- горизонтального скролла страницы нет; прокручивается только лента маршрутов.
- в шагах планирования и выбора состава global tab bar скрыт, чтобы не конкурировать с critical flow.

## Решённые продуктовые вопросы

- chooser реализован bottom sheet, а не modal;
- финальный каталог — плотная горизонтальная лента как в утверждаемом референсе; вертикальный список и одиночная hero-карточка отклонены, потому что вытесняют историю ниже первого экрана;
- route preview — отдельный routable экран, а не sheet: так последовательность точек помещается без вложенного скролла;
- route template и реальный upcoming raid визуально разведены: изображение-каталог против компактной календарной строки;
- один `ParticipantPicker` используется для быстрого старта, маршрута и планирования;
- route cards сохраняют плотность референса, а описание и примерная длительность раскрываются в preview;
- desktop использует те же четыре блока с сеткой 2 + 3 колонки, без отдельной информационной архитектуры.

## Ограничения дизайн-задачи

- нет вызовов API, сохранения в БД и изменения lifecycle рейда;
- нет production-CRUD шаблонов и административных ролей;
- данные и изображения демонстрационные;
- физический smoke на реальном телефоне и явное `UX approved` выполняются Павлом как финальный acceptance gate;
- интеграция с каноническими raid endpoints выполняется в следующих исполнительных задачах после `UX approved`.
